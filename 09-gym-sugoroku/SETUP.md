# ジムすごろく（Let's Go Mt.Fuji！！）セットアップ手順

週1回ジムに行ったらスタンプを押し、40マスで富士山を目指す LINE Bot。
仕組みは `04-food-expiry` と同じ（LINE Messaging API ＋ Google Apps Script ＋ スプレッドシート）。

```
 [ LINE ]  リッチメニュー「すごろく」「コイン」 ──→ すごろくの画面（GAS の Web アプリ）
    │          「状況」                                  │ スタンプ・コインを記録
    │ Webhook                                             ▼
 [ Google Apps Script ] ─────────────────→ [ スプレッドシート「ジムすごろく」]
    │
    ├ 水曜20時台：今週まだなら「行けそう？」
    ├ 日曜17時台：今週まだなら「行けそう？」（コインがあれば「コインを使う」ボタン付き）
    └ スタンプを押したら：本人に「がんばったね」、夫にお知らせ
```

所要時間：40〜50分。

---

## 1. LINE で Bot を作る（15分）

消費期限の Bot とは**別のチャネル**を作る（push の無料枠が別になり、メニューも混ざらない）。

1. https://developers.line.biz/console/ → 消費期限 Bot と同じプロバイダーでよい
2. **新規チャネル作成 → Messaging API**
   - チャネル名：例「ジム手帳」（トークの相手として表示される名前）
3. **Messaging API 設定**タブ
   - 「チャネルアクセストークン（長期）」→ **発行** → コピー（`LINE_CHANNEL_ACCESS_TOKEN`）
   - 「応答メッセージ」を **オフ**（オンだと定型文が二重に返る）
   - 「Webhook の利用」は **オン**（URL は手順4で設定）
4. QR コードから、**自分と奥さんの LINE で友だち追加**しておく

---

## 2. GAS のプロジェクトを作る（10分）

1. https://script.google.com/ → **新しいプロジェクト**（名前は「ジムすごろく」など）
2. clasp を使う場合（おすすめ。手順は `04-food-expiry/SETUP.md` の付録と同じ）:
   ```bash
   cd 09-gym-sugoroku
   clasp clone <スクリプトID> --rootDir .     # .clasp.json ができる（git には入らない）
   git status                                 # clone でファイルが上書きされていないか確認
   clasp push                                 # 上書きされていたら、git で戻してから push する
   ```
   clasp を使わない場合は、GAS エディタで次のファイルを作って中身を貼る：
   `logic.gs` `main.gs` `webapp.gs` `security.gs` `RichMenuImage.gs`（スクリプト）、`web`（HTML）、
   `appsscript.json`（プロジェクトの設定で「マニフェストを表示」にチェック）
3. **プロジェクトの設定 → スクリプト プロパティ** に追加：

   | プロパティ | 値 |
   |---|---|
   | `LINE_CHANNEL_ACCESS_TOKEN` | 手順1のトークン |

4. 関数 `setupSpreadsheet` を実行（初回は権限の承認が出る）
   → スプレッドシート「ジムすごろく」ができ、`SPREADSHEET_ID` が自動で入る

---

## 3. デプロイする（5分）

1. 右上 **デプロイ → 新しいデプロイ → ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（LINE のサーバーから届くため必須）
2. 表示された **ウェブアプリの URL**（`…/exec`）をコピーし、スクリプトプロパティ **`WEB_EXEC_URL`** に貼る
   （GAS エディタから実行すると別の URL が返ることがあるため、ここで固定しておく）

---

## 4. LINE と GAS をつなぐ（3分）

1. 関数 `setupWebhookSecret` を実行 → ログに `…/exec?s=xxxxxxxx` が出る
2. LINE Developers の **Webhook URL** にそれを貼る → **更新** → **検証**（成功すれば OK）

---

## 5. 使う人を登録する（5分）

1. 奥さんと自分が、それぞれ Bot に `id` と送る → userId が返ってくる
2. スクリプトプロパティに追加：

   | プロパティ | 値 |
   |---|---|
   | `PLAYER_USER_ID` | 奥さんの userId（すごろくをする人。声かけ・ほめる言葉の送り先） |
   | `WATCHER_USER_IDS` | 自分の userId（お知らせを受け取る人。複数ならカンマ区切り） |

   この2つに入っていない人には、Bot は `id` 以外反応しない。

---

## 6. メニューと声かけを設定する（3分）

1. 関数 `setupRichMenu` を実行 → 2人にメニューが付く（トークを開き直すと出る）
2. 関数 `setupTriggers` を実行 → 水曜20時台・日曜17時台の声かけが入る
3. 関数 `testConfig` を実行 → 設定がそろっているか確認できる

---

## 7.（任意）Google の注意バーを消す

GAS の画面を直接開くと、上に「Google Apps Script のユーザーによって作成されたもの」という
注意バーが出る。消したいときは、GitHub Pages の枠ページ（`docs/gym/index.html`）を挟む。

1. このブランチを `main` に取り込む（Pages は `main` の `docs/` から配信している）
2. スクリプトプロパティ **`WEB_FRAME_URL`** に `https://shun-7778.github.io/04-food-expiry-bot/gym/` を入れる
3. `setupRichMenu` をもう一度実行する（メニューのリンクが枠ページ経由に変わる）

## 使い方

| 操作 | どこで | 動き |
|---|---|---|
| ジムに行った | メニュー「すごろく」→「今週ジムに行った！」 | 1マス進む（週1回まで）。本人に「がんばったね」、夫にお知らせ |
| 同じ週にもう1回行った | メニュー「コイン」→「今週もう1回行った！」 | コイン1枚（1日1枚まで） |
| 今週は行けない | 「コインを使う」／日曜の声かけのボタン | コイン1枚で今週を埋める。あとで行けたら「スタンプに変える」でコインが戻る |
| コインが5枚たまった | コイン画面 | 「手作りお菓子」と交換するか、ためておくかを選べる |
| 進み具合を見る | メニュー「状況」／`状況` と送る | マス数・次のご褒美まで・コインを返信 |
| 押し間違えた | 画面の一番下「最後のスタンプ（コイン）を1つ消す」 | 行は消さず「取消」にする |

### ご褒美

| マス | 週1で続けた場合 | 中身 |
|---|---|---|
| 6・31 | 11月末・5月中旬 | プチご褒美：マッサージ |
| 18 | 2月中旬 | プチご褒美：マカロン |
| 11 | 12月末 | 登山靴 |
| 24 | 3月末 | ジャケット／パンツ |
| 37 | 6月末 | 帽子とサングラス |
| 40 | 7月後半 | ゴール（富士山へ出発！） |
| コイン5枚 | — | 手作りお菓子 |

中身を変えるときは `logic.gs` の `GYM_SPECIAL` と `GYM_COIN_REWARD` を直す。
**夫へのお知らせには中身が書かれる**（準備できるように）。本人へのメッセージには書かない。
ご褒美のマスは、本人が画面で箱を開けた時点で夫に知らせる（開ける前に×で取り消したときは知らせない）。

### 記録シート

| 列 | 内容 |
|---|---|
| ID / 登録日時 | 自動 |
| 種類 | スタンプ / コイン穴埋め / コイン / ご褒美交換 |
| 日付 | その操作をした日（`yyyy-MM-dd`） |
| スタンプ / 角度 | 押したスタンプの絵柄と傾き |
| 見出し / ことば | ほめる言葉（押したマスをタップすると同じ画面が出る） |
| 状態 | 有効 / 取消 |

行を直接直してもよい（画面は開くたびにシートから作り直す）。

---

## LINE の送信数

無料枠は**月200通の push**（相手1人につき1通と数える）。
1週間あたり、本人への「がんばったね」1通＋夫へのお知らせ1通＋声かけ0〜2通で、月におよそ10〜20通。
LINE から操作したとき（日曜の「コインを使う」ボタン、「状況」）は返信なので数えない。

## セキュリティ

`04-food-expiry/SETUP.md` の「セキュリティの考え方」と同じ。
- Webhook は URL の `?s=`、画面は URL の `?k=` が合言葉。メニューの URL は人に転送しない
- 画面の URL が漏れた疑いがあるときは `rotateWebToken` → `setupRichMenu` を実行する

## コードを直したとき

```bash
cd 09-gym-sugoroku
clasp push
clasp deploy -i <デプロイID> -d "説明"   # これをしないと LINE 側は古いまま
```

直したら、push の前に手元で動作確認を流す（Node.js と Windows の Edge が要る）。

```bash
node test/gas.test.js    # サーバー側：シート・LINE を偽物にして、記録と送信内容を確かめる（48項目）
node test/web.test.mjs   # 画面：Edge をスマホ幅で開き、押す・開ける・交換などを操作する（34項目）
```

リッチメニューの画像を変えるときは `richmenu.html` を直して `node richmenu.mjs`
（Windows の Edge で撮影して `richmenu.png` と `RichMenuImage.gs` を作る）→ `clasp push` → `setupRichMenu`。
